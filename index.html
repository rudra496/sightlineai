Problem & mission

Many accessibility tools fail in low-connectivity or high-uncertainty environments. SightlineAI exists to deliver practical, safety-first guidance that still works when cloud AI is unavailable.

Core features

Qwen guidance
Structured responses with action, safety, and confidence notes.
Image input
Safe upload pipeline with validated types and fallback analysis.
Voice input/output
Speech recognition (when supported) and speech synthesis.
Memory/history
Session memory panel with restore, pin, and clear flows.
Offline fallback
Deterministic fallback guidance when network/model fails.
Edge-ready + geospatial
Risk scoring endpoint and future sensor-fusion hooks.

How it works

  1. User submits text, voice transcript, or image plus route context.
  2. Backend validates payloads and attempts Qwen guidance.
  3. If unavailable, deterministic fallback returns labeled offline guidance.
  4. Guidance is returned as structured JSON and saved to session history.

Architecture

Frontend → FastAPI → Qwen / fallback → memory store → accessible output. Includes image route, edge context scoring, and geospatial hooks.

  • Structured error schema with request IDs.
  • No committed .env files.

FAQ

Does it work offline? Yes, via deterministic fallback guidance endpoint and automatic fallback in /api/guidance.

Does it support image and voice? Yes. Image upload is validated server-side; voice uses browser speech APIs when available.

Tech stack? FastAPI, Qwen OpenAI-compatible API, plain HTML/CSS/JS frontend.
